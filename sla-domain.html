Create SLA Domain

SLA Domains are policies that define how objects in RSC are backed up. In this flow, users set up an SLA Domain based on their requirements.

Type: Pattern → Product flow Figma ↗ Updated Oct 2024 Owners: yuki.zhang, anara, noa

Goal & preconditions

Goal: create a custom SLA Domain to streamline and customize workload protection.

Actors: RSC user/admin.

Precondition: for archival, archival locations must first be added in RSC settings.

Core flow

Five core steps, which apply to all object types in RSC.

  1. Select object types

    The user selects one or more object types that can be protected by this SLA Domain.

  2. Frequency and retention

    [NEEDS TEXT — behind tab] how often backups run and how long they're kept.

  3. Archival
    Secondary backups

    Set up an archival policy to store data long-term in a cost-effective location. The policy defines: (1) the source location data is archived from, (2) the archival location where it's stored, and (3) when data is sent there. Requires archival locations already added in RSC settings.

    Archival enabled

    Input fields appear progressively for a smooth experience.

    Archival disabled

    [NEEDS TEXT — behind tab]

  4. Replication
    Secondary backups

    Configure a replication policy to store data in more than one location, generally to ensure a copy survives a disaster. The policy defines the replication target and how long data is retained there.

    Replication enabled

    User configures the replication target and the retention period.

    Replication disabled

    [NEEDS TEXT — behind tab]

  5. Confirmation

    [NEEDS TEXT — behind tab] review and confirm the SLA Domain.

Optional steps

  1. FTUX Introduction
    When: first-time users

    Describes SLA Domains and key concepts. Users can check "Do not show again" (bottom-left of the modal) to skip this page.

  2. Object Type Details
    When: some object types allow configuring more backups; varies by object

    Shown after the Replication step and before Retention Lock. Example: vSphere VMs (virtual machines).

  3. Retention Lock

    Ensures snapshots aren't deleted during the retention period, whether by accident or by bad actors. Used in governance or compliance mode.

    Governance mode

    Reducing the SLA Domain's retention period requires approval of at least two users.
